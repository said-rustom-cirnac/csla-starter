# CSLA Starter: Plan Roadmap

**Spec:** `docs/superpowers/specs/2026-11-12-csla-starter-design.md`
**Jira:** Story DEV-38 (Epic DEV-37). Branch per plan: `DEV-38-<slug>`, cut from `claude`, merged into `claude` by PR.

The spec has seven delivery phases that build on each other. There is one plan per phase. Each plan:

- ends in working, tested software;
- is written only after the previous plan is merged, so it can use the code that actually exists.

| Plan | Branch | Delivers | Main things later plans rely on |
|---|---|---|---|
| 1 Foundation | `DEV-38-foundation` | git layout (`main`/`claude`), solution skeleton, build rules, architecture tests, CI, CodeQL, Dependabot, `claude`→`main` sync and guard, Claude docs skeleton, GitHub rulesets | `CslaStarter.slnx`, the 7 `src` projects, `tests/CslaStarter.Architecture.Tests` with `RepoPaths`, `.github/claude-only-paths.txt`, `scripts/sync-main.sh` |
| 2 Data and security core | `DEV-38-data-security` | Core contracts, PostgreSQL + EF Core (snake_case, `xmin`), DB roles, migration bundle, audit interceptor + tables + trigger, security events, Data Protection keys, Entra ID + mock OIDC, claims transformation, `bootstrap-admin`, headers/CSP, culture endpoint, idle timeout, docker-compose, Integration.Tests | `ICurrentUser`, `IDataAccessContext`, `AppDbContext`, `IAuditHistoryReader`, `ISecurityEventLog`, `TestAuthHandler` |
| 3 Business layer | `DEV-38-business` | CSLA config, `App*Base` classes, `CslaType<T>` + types, `HasRole` rule, `LocalizedDisplayName` + resources, record-level access, Users/Roles + Projects/Tasks/Members, DALs, Business.Tests, class-layout convention test | business objects, DAL interfaces, `IEntityIdentity`, `PropertyHasRule` |
| 4 Realtime | `DEV-38-realtime` | `IEntityChangeHub` + change publishing, PostgreSQL backplane, presence, draft store, access-changed notices | `Subscribe(topic, handler)`, `IPresenceTracker`, `IDraftStore` |
| 5 Components | `DEV-38-components` | `CslaBaseComponent` family, `AppViewModel<T>`, GCDS interop, every behaviour in spec §12.3, unstyled sample pages, Components.Tests | component APIs for the UI phase |
| 6 Hardening and packaging | `DEV-38-hardening` | E2E + axe, remaining convention tests, `dotnet new` template with `--claude`, release workflow (template `.nupkg` + SBOM), complete guides and Claude skills | template package |
| 7 UI | later | GC Design System layout and styling (Impeccable) | none |
