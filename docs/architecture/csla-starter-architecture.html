3

Architecture

The browser only receives the rendered screen. Every rule and permission check runs in the CSLA business layer on the server before any data reaches the database.

4

Live updates

A save only reaches the screens that have that record open, so the cost grows with the number of viewers, not with the number of users.

5

Security

Access is denied by default and checked at four levels. The template meets the Protected B controls below before an app adds a single feature.

  1. PageSigned-in users only. Pages declare the roles they need.
  2. RecordUsers only load records they're entitled to see. Edit and delete are checked per record.
  3. FieldWho may see or change each field. Hidden or read-only automatically.
  4. DatabaseThe app's account can't change schema or edit the audit trail.
ITSG-33 controlHow the starter meets it
AC-3 · AC-6Access enforcement, least privilegeDeny by default. Role checks on pages and individual fields. Each user only ever loads the records they're entitled to. The app connects to the database with a data-only role.
AC-11 · AC-12Session lock and termination20-minute idle timeout with a 2-minute warning, and an 8-hour absolute limit. Unsaved work is kept as a draft.
AU-2 · AU-3 · AU-12Audit events and contentEvery change records user, time, field, old value and new value. Sign-ins, access denials and role changes are logged.
AU-9Protection of audit informationThe app can only add audit rows. A database trigger blocks edits and deletes.
IA-2Identification and authenticationEntra ID single sign-on, with MFA enforced through Conditional Access.
SC-8Transmission confidentialityHTTPS with HSTS. TLS to the database with certificate verification.
SC-12 · SC-28Key management, data at restEncryption keys are stored in the database, protected by a certificate (IIS) or Key Vault (Azure). Drafts are encrypted. Azure data stays in Canada Central or Canada East.
SC-18 · SC-23Mobile code, session authenticityA strict Content Security Policy allows scripts only from our own server. Host-only, secure, HttpOnly cookies. Antiforgery tokens on every form.
SI-10 · SI-11Input validation, error handlingAll validation runs on the server, in CSLA. Users see a reference number, never system details.
RA-5 · SA-11Vulnerability scanning, developer testingThe build fails on vulnerable packages. CodeQL scanning, automated security tests, and a software bill of materials with each release.

Also built in: WCAG 2.1 AA accessibility (EN 301 549), English and French under the Official Languages Act, and Federal Identity Program elements in the page shell.

6

Audit and history

Every change is recorded with its old and new values, and any record can show its full history to the people allowed to see it.

  • AutomaticChanges are captured in the same database transaction as the save, so no change can be saved without its audit record.
  • Permission-awareFields a user can't read aren't shown. Sensitive fields record that they changed, without the values.
  • Tamper-resistantThe app can only add audit rows. Edits and deletes are blocked in the database.
  • TraceableEach entry carries the same reference number as the logs, for investigations.
7

Reusable components

All screen components inherit one base component, so each behaviour is written and tested once. A field never repeats a rule. Its label, required marker, length limit, errors and permissions all come from the CSLA object.

Rules on screen

  • Required marker from rules
  • Length limit from rules
  • Errors, warnings, information
  • "Checking…" for slow rules
  • Error summary with focus

Protecting work

  • Unsaved-changes guard
  • Drafts and recovery
  • Cancel restores values
  • "Someone saved first" handling
  • Language switch keeps edits

Working together

  • Live refresh
  • "Jane is also editing"
  • Changed fields highlighted
  • Field history

Security

  • Fields hidden or read-only by role
  • Buttons follow permissions
  • Masked fields, audited reveal
  • Session timeout warning

Feedback

  • Busy state
  • Bilingual notifications
  • Screen reader announcements
  • Errors with reference number

Operations

  • Keyboard shortcuts
  • Load and save timing per screen
  • Work stopped when you leave a page

Risks

RiskLevelMitigation
Blazor Server keeps a live connection per user, which needs sticky sessions and server memoryMediumDrafts survive dropped connections. Connection limits are configured. Load test before the first production app.
Direct database edits bypass the app's audit trailMediumRestricted database accounts, triggers that block audit changes, database-level auditing (pgAudit) for administrators.
No official GC Design System package for BlazorMediumThin wrappers pinned to version 1.7, which promises a stable API across 1.x. Covered by component and browser tests.
CSLA is a specialised skillMediumStep-by-step guides, scaffolding and tests in the template. CSLA is open source (MIT) and actively maintained.
A live-update notice can be missed during a network blipLowScreens resync after reconnecting. The version check on save still prevents lost updates.
.NET 10 support ends November 2028LowDocumented upgrade path to the next long-term release. Centrally managed package versions keep upgrades small.
